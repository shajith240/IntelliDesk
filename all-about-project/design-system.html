Design System

The visual language: HSL color tokens with a light and a dark theme, how they map to Tailwind v4 utilities, typography, motion and reduced motion, component variants, and the conventions that carry meaning (status, priority, AI output, internal notes, confidence).

Tokens & theming

How are colors defined?Intermediate

As CSS custom properties holding bare HSL components (--primary: 215 90% 47.1%) on :root for light mode and on .dark for dark mode. Storing the components rather than a full color lets utilities add opacity (hsl(var(--primary) / 0.5)). Groups: surfaces (background, sunken, raised, overlay), text (foreground, subtle, subtlest), borders, fills, primary, and semantic pairs of base / subtle / text for danger, warning, success, info and discovery, plus priority colors.

--danger: 4 64.1% 48%;
--danger-subtle: 3 100% 96.1%;
--danger-text: 4 65.7% 41.2%;
--warning: 47 97.4% 44.9%;
--warning-subtle: 48 100% 92%;
--warning-text: 26 100% 32.4%;
src/app/globals.css:12-74 (light), 76-129 (dark), 44-49
How do tokens become Tailwind classes?Intermediate

Tailwind v4 is configured in CSS. An @theme inline block maps each variable to a Tailwind theme key (--color-warning-subtle: hsl(var(--warning-subtle))), which generates utilities like bg-warning-subtle and text-warning-text. Radius (sm 3px, md 4px, lg 8px, xl 12px), elevation shadows and font families are mapped the same way. There is no tailwind.config.js.

src/app/globals.css:131-195
How does dark mode work?Basic

next-themes sets a .dark class on <html> (light by default, system preference supported, transitions disabled during the switch to avoid flashes). A custom variant makes Tailwind's dark: follow that class rather than the OS setting, and the .dark block redefines every token, so components don't need per-mode classes. The switch is the theme menu in the top bar.

@custom-variant dark (&:where(.dark, .dark *));
src/app/globals.css:9-10; src/app/providers.tsx:26; src/components/layout/theme-menu.tsx
What typography is used?Basic

Three families loaded with next/font/google (self-hosted, no layout shift): IBM Plex Sans for the UI, IBM Plex Mono for ticket numbers, codes and timestamps, and Fraunces as the display face. They are exposed as CSS variables and mapped to font-sans, font-mono and font-display.

src/app/fonts.ts:7-30; src/app/globals.css:192-194
How are motion and reduced motion handled?Intermediate

A small set of named keyframes (id-fade-*, id-pop-*, id-dialog-in, sheet slide-ins, toast, skeleton shimmer, and slow drifting fields for the login hero) is shared by all components. A global prefers-reduced-motion: reduce rule shortens every animation and transition to 0.01 ms, so motion is off everywhere for users who ask for it.

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
src/app/globals.css:240-250, 273-300, 302-309
How is focus shown?Basic

A base :focus-visible outline, placed inside @layer base so component utilities (outline-none, focus-visible:ring-*) can override it. Putting the reset in a layer fixed a bug where the global focus ring showed up on components that had explicitly removed it.

src/app/globals.css:201-221

Components

How are component variants built?Intermediate

With class-variance-authority: a component declares its variants and sizes once, and cn() (clsx + tailwind-merge) resolves conflicts when callers add classes. Buttons have default, primary, subtle, danger, discovery and link variants, several sizes, and a loading state.

variant: {
	default: "bg-fill text-subtle hover:bg-fill-hover hover:text-foreground active:bg-fill-pressed",
	primary: "bg-primary text-primary-foreground hover:bg-primary-hover",
	subtle: "bg-transparent text-subtle hover:bg-fill hover:text-foreground active:bg-fill-hover",
	danger: "bg-danger text-on-bold hover:bg-danger/90",
	discovery: "bg-discovery text-on-bold hover:bg-discovery/90",
	link: "text-primary underline-offset-4 hover:underline",
src/components/ui/button.tsx:13-19; src/lib/utils.ts
How are ticket statuses shown?Basic

As lozenges (small uppercase labels) whose appearance comes from one map: New = default (grey), In Progress = inprogress (blue), Pending = moved (amber: waiting on the customer), Resolved and Closed = success (green). Every status display (lists, header, analytics) uses StatusLozenge, so adding a status meant one entry.

src/lib/ticket-meta.ts (STATUS_META); src/components/ui/lozenge.tsx
How is priority conveyed without relying on color?Basic

Each priority has a distinct icon shape as well as a color: P1 double chevron up (Highest), P2 chevron up (High), P3 equals (Medium), P4 chevron down (Low), with a text label where space allows. Color-blind users can tell them apart by shape.

src/components/ui/priority-icon.tsx:2-20; src/lib/ticket-meta.ts (PRIORITY_META)
How is AI output and AI confidence shown?Intermediate

Anything produced by the model carries the IntelliDesk AI mark (a monogram, not a sparkle icon) with a label: "AI summary"/"AI suggestion", "AI draft", "Sent automatically". Confidence is a five-segment meter filled in proportion to the score, colored by band, with a text summary so it isn't color-only:

ScoreBandSummary
≥ 85successHigh confidence
70–84infoModerate confidence — spot-check
50–69warningLow confidence — review carefully
< 50dangerVery low confidence — verify everything

How do internal notes and delivery states look different from customer-facing messages?Basic

Internal notes use the warning palette (amber background and border), a lock icon and an "Internal note" lozenge, and the composer turns amber in note mode with "Only your team sees notes" — so nobody confuses a note with a reply. Replies show "Sending…" (inprogress) or "Not delivered" (removed/danger, with the error text).

src/features/ticket-workspace/components/conversation-column.tsx; reply-composer.tsx
How is the SLA state shown?Basic

SlaBadge shows time remaining or how long ago the target was breached, colored by state (on track, at risk, breached) with an icon and a full-date tooltip; the ticket sidebar shows first-response and resolution targets separately.

src/components/ui/sla-badge.tsx; src/features/ticket-workspace/components/ticket-sidebar.tsx
How are loading, empty and error states handled?Basic

Every data view has all three: skeletons shaped like the final content (shimmer animation), an EmptyState with an icon, title and description ("Nothing in spam"), and an ErrorState with a retry button. Inline problems use SectionMessage (information, warning, error, success, discovery).

src/components/ui/skeleton.tsx; empty-state.tsx; error-state.tsx; section-message.tsx
How does the ticket workspace adapt to screen size?Intermediate

From the md breakpoint it's a two-column grid: conversation and docked composer on the left, a 320 px (360 px on xl) details sidebar on the right. Below that, the same content becomes two tabs, Conversation and Details. Ticket lists use container queries instead, so they drop columns based on their own width.
