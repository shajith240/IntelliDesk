System Architecture

How the pieces fit: one Next.js application on Vercel that serves the UI and the API, a server-only layer that alone holds secrets, Supabase Postgres as the system of record, Pinecone for vectors, Gemini for AI, the company's own mailbox over IMAP/SMTP, and a GitHub Actions schedule that drives email intake.

Why is it a single Next.js app rather than a separate frontend and backend?Basic

Route handlers give a real server-side API (secrets, database access, SMTP) in the same deployable as the UI: one repository, one build, one Vercel project, shared TypeScript types between client and server (src/types/api.ts). The only work that isn't request/response, email polling, is triggered over HTTP by a scheduler rather than needing a separate worker.

Request lifecycle & boundaries

Walk through an authenticated API call.Intermediate
  1. The browser calls e.g. GET /api/tickets/… through apiGet (SWR) with the NextAuth cookie.
  2. requireAuth() decodes the JWT; the JWT callback has re-validated role, active flag and organization within the last 5 minutes.
  3. getOrgId(session) takes the organization from the session, never from the request body.
  4. can.viewTicket / can.workTicket decide access; agents get 404 for tickets that aren't theirs.
  5. The handler queries through supabaseAdmin (service role) with .eq("organization_id", orgId) on every query.
  6. Multi-row writes go through a Postgres function (assign_ticket, complete_ticket_reply, record_inbound_message) so they are atomic.
  7. The JSON response matches a type in src/types/api.ts; SWR caches it and refreshes after mutations.

How is the client/server boundary enforced?Intermediate

Three guards: every secret-bearing module imports server-only (importing it from a client component fails the build); ESLint's no-restricted-imports forbids @/server/* from client code and cross-feature imports; and only NEXT_PUBLIC_* variables reach the browser, none of which are secrets. The Supabase client is created lazily on first use behind a proxy, so importing the module has no side effects.

How is multi-tenancy implemented end to end?Advanced
  • Identity: the organization comes from the signed session.
  • Queries: every query filters by organization_id; lookups like threading and ticket numbers are org-scoped.
  • Database: composite (id, organization_id) foreign keys make cross-tenant references impossible; RLS is closed to browser roles.
  • Vectors: Pinecone namespaces per organization ({orgId}_emails, _tickets, _faqs).
  • Secrets: encrypted with the organization id as associated data, so they only decrypt in their own row.
  • Numbers: ticket numbers are counted per organization, so tenants can't infer each other's volume.

Background work without a job server

How does email get in if there's no background worker?Advanced

A GitHub Actions schedule calls POST /api/emails/poll every 10 minutes with the cron secret (Vercel Cron calls it daily as a fallback). One run has two phases within a 50-second budget: ingest (for each connected mailbox, fetch unseen mail, store each message as an unprocessed emails row, only then mark it read) and drain (process stored rows oldest first, claiming each with a compare-and-set, pausing 4 seconds between emails to stay under AI rate limits). The emails table is the queue; a message failing 5 times is parked with its error.

Why no realtime updates?Intermediate

Supabase Realtime authorizes subscriptions with Supabase Auth and RLS; this app uses NextAuth and keeps the database closed to browser roles. Instead, SWR refreshes every 30 seconds and after every mutation, and the top bar shows whether the last refresh succeeded ("Up to date" / stale).

What is deliberately not part of the architecture?Basic
Not implemented No payments or billing; no websockets/realtime; no message broker or worker process (the queue is a table drained by HTTP-triggered runs); no attachment storage (attachments are ignored); no business-hours SLA calendar; no password-reset emails; no workspace branding UI yet; no committed end-to-end test suite.
