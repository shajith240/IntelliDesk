Deployment & Operations

How the app is deployed, every environment variable and secret, how schema changes reach the live database, and the runbook for the problems an operator actually meets.

Deploying

How does code reach production?Basic

Vercel builds and deploys every push to main (Next.js preset, root directory empty, npm run build). Before pushing, the local gate is typecheck, lint, unit tests and a production build; database changes are applied separately with the Supabase CLI, in an order that keeps the running code working (below).

npx tsc --noEmit -p .
npm run lint
npm test
npm run build
package.json (scripts: dev, build, start, lint, test); README.md "Deploying to Vercel"
How is email polling scheduled in production?Basic

Two callers of /api/emails/poll, both sending Authorization: Bearer $CRON_SECRET: a GitHub Actions workflow every 10 minutes (the real schedule) and a Vercel Cron once a day at 06:00 UTC (fallback — the most Vercel Hobby allows).

{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "crons": [{ "path": "/api/emails/poll", "schedule": "0 6 * * *" }]
}
vercel.json; .github/workflows/poll-mailboxes.yml:1-6

The workflow needs two repository secrets: APP_URL (deployed URL, no trailing slash) and CRON_SECRET (same value as on Vercel). Without them it skips with a warning.

What's needed to run a production build locally?Basic

npm run build then AUTH_TRUST_HOST=true npm start. Auth.js rejects requests from untrusted hosts outside Vercel/next dev, so the flag is required for a local next start.

Database changes

How is a migration applied to the live database?Intermediate
  1. Rehearse: run the migration body and every test suite inside BEGIN … ROLLBACK against the live database.
  2. Back up the affected tables with pg_dump --data-only.
  3. supabase db push (the CLI is linked to the project and records applied versions).
  4. NOTIFY pgrst, 'reload schema' so the API sees new relationships.
  5. Run all suites again:
for f in supabase/tests/*.sql; do psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f "$f"; done
README.md "Database"; supabase/tests/*.sql
In what order are schema changes and code deployed?Advanced

Expand/contract. Additive migrations (new tables, relaxed constraints) go first — the running code ignores them. Then code that uses the new shape is deployed and confirmed live. Only then does a contract migration drop what nothing uses. Migration 012 (expand) was applied, commit ffccba5 deployed and verified, and only then 013 (contract) was applied. A bridge trigger in 009 covered the window in which old code still wrote to ticket_emails.

supabase/migrations/012_normalize_expand.sql:1-3; 013_normalize_contract.sql:1-3; see database-design.html

Runbook

A mailbox shows "Needs attention". What do you do?Basic

The card shows the last error in plain language (usually a revoked or wrong app password). Create a new Gmail app password and use Reconnect: the new credentials are verified before replacing the old ones. Polling resumes on the next run; nothing was lost because unread mail stays unread until stored.

src/server/email/mailbox.ts (describeMailboxError, recordMailboxSync); src/features/settings/components/mailbox-form.tsx
Emails aren't becoming tickets. How do you debug it?Intermediate
  1. GitHub → Actions → "Poll support mailboxes": did the last runs succeed? The response JSON shows intake and drain counts.
  2. Settings → Support mailbox: connected and healthy?
  3. Settings → AI: is a key configured and healthy? Without one, email waits in the queue.
  4. Queue rows: select processing_attempts, processing_error from emails where not processed. A row at 5 attempts is parked; saving a working AI key requeues rows that gave up, otherwise reset processing_attempts to 0.
  5. Spam page: was it caught by a filter? "Not spam" requeues it.
src/server/email/intake.ts:16; src/app/api/settings/ai/route.ts (requeue); src/app/api/emails/[id]/not-spam/route.ts
How do you rotate secrets?Intermediate
  • CRON_SECRET: change it on Vercel and in the GitHub repository secret at the same time, then redeploy.
  • NEXTAUTH_SECRET: changing it signs everyone out.
  • Supabase service-role key / database password: rotate in the Supabase dashboard, update Vercel.
  • MAILBOX_ENCRYPTION_KEY: there is no re-encryption tool yet; a new key makes stored credentials unreadable, so every workspace must reconnect its mailbox and re-enter its AI key. (The v1: ciphertext prefix exists so a versioned rotation can be added.)
  • User passwords: each user changes their own from the user menu; there is no reset email yet.
src/server/crypto/secrets.ts:12; src/app/api/me/password/route.ts
How do you delete audit data or a whole workspace?Advanced

The audit log is append-only. Deliberate maintenance must opt in within the transaction; otherwise the trigger refuses the delete (this includes the cascade from deleting an organization):

BEGIN;
SET LOCAL intellidesk.audit_maintenance = 'on';
DELETE FROM public.audit_logs WHERE created_at < now() - interval '1 year';
COMMIT;
Usage example (not copied from a file); the rule it satisfies: supabase/migrations/012_normalize_expand.sql:102-146
What about backups and uptime?Basic
Operational gaps The free Supabase plan has no automatic backups; manual pg_dump backups were taken before each migration. There is no uptime monitoring or error tracking service configured. Before a paying customer: Supabase Pro (daily backups), Vercel Pro (commercial use), and a free uptime monitor.
