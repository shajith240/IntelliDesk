Agent Opens Ticket & Sends Response: End-to-End Flow

Trace how an agent opens a ticket from the list, reviews the AI-generated draft reply, edits it, and sends the response to the customer. Follow the state management, validation, email sending, and the exact success and failure messages the user sees.

Step 1: Opening a Ticket via URL Parameter

How does clicking a ticket open it in the workspace?Basic

The ticket ID is stored in the URL query parameter ?ticket=<id>. When an agent clicks a ticket, the useTicketParam() hook reads searchParams.get("ticket") and updates the URL via router.push(), triggering a re-render. The TicketWorkspace component conditionally opens a Sheet drawer if ticketId is present. This approach persists the open ticket across browser refresh and back/forward navigation. Closing the drawer removes the ticket param from the URL.

// src/hooks/use-ticket-param.ts
export function useTicketParam() {
	const router = useRouter();
	const pathname = usePathname();
	const searchParams = useSearchParams();
	const ticketId = searchParams.get("ticket");

	const setTicket = useCallback(
		(id: string | null) => {
			const params = new URLSearchParams(searchParams.toString());
			if (id) params.set("ticket", id);
			else params.delete("ticket");
			const qs = params.toString();
			const href = qs ? `${pathname}?${qs}` : pathname;
			if (id) router.push(href, { scroll: false });
			else router.replace(href, { scroll: false });
		},
		[pathname, router, searchParams],
	);

	return { ticketId, openTicket: (id) => setTicket(id), closeTicket: () => setTicket(null) };
}

Step 2: Finding and Displaying the AI Draft

How does the system identify which AI draft to show the agent?Intermediate

The ticket's auto_responses array contains all pending and sent responses. The useReplyDraft() hook filters for unsent responses (sent=false), sorts by created_at descending, and returns the latest one as pending. If no unsent response exists, pending is null. This pattern ensures the UI always shows the most recent AI-generated draft, and prevents stale drafts from being displayed if a new one was regenerated server-side.

// src/features/ticket-workspace/hooks/use-reply-draft.ts:13-46
function latestByCreatedAt(rows: AutoResponseRow[]): AutoResponseRow | null {
	if (rows.length === 0) return null;
	return rows.reduce((latest, row) =>
		new Date(row.created_at).getTime() > new Date(latest.created_at).getTime() ? row : latest,
	);
}

How is the draft text stored and recovered across page refreshes?Intermediate

Text edits are saved to browser localStorage under a key like intellidesk.draft.<ticket_id>.<response_id>. On initial load, if localStorage has a value for that key, it's used; otherwise the AI's response_text is used. If the user edits the text (making it differ from the AI's original), the edited version is persisted to localStorage. Closing and reopening the ticket (or switching between tickets) recovers the locally-stored draft. If localStorage is unavailable (private mode, quota exceeded), edits still work in memory for the current session but don't persist. A "Restore AI Draft" button lets the agent revert to the original AI text.

Step 3: Sending the Response

What validation happens before sending a response?Intermediate

Client-side validation in useReplyDraft.send(): text must not be empty after trimming, and must be ≤ 20,000 characters. Server-side validation in POST /api/respond: the response_id (or ticket_id if response_id not provided) must resolve to an unsent auto_response row owned by the caller's organization; response_text must not be empty and must be ≤ 20,000 characters. If any validation fails, a 400 error is returned with a descriptive message shown to the user.

What exactly happens when the response is sent via the API?Advanced

The flow is: (1) Validate session and get organization_id, (2) Find the auto_response row by response_id or ticket_id (must be unsent and in the caller's org), (3) Fetch the email row to get the customer's from_address, (4) Fetch the organization's SMTP config, (5) Call sendEmail() to email the customer with the response text (wrapped in HTML, in-reply-to the original email), (6) Update auto_responses row: set sent=true, sent_at=now, response_text=trimmed_user_text, (7) Update tickets row: set status="Resolved", sla_resolved_at=now, and if sla_first_response_at is null, set it to now (marking the first response time), (8) Insert audit_logs entry with action="response_sent" and response details, (9) Return 200 success. If email sending fails (SMTP error), return 502. If any database update fails, return 500.

Step 4: Success and Error Handling

What user-facing messages does the agent see on success and on each failure?Advanced

On success: a green success toast appears with the title "Response sent to {recipient}" and the description "The ticket is now Resolved." The draft is cleared from localStorage, the status moves to "sent", and all unrelated data is refreshed via refreshAll(). On specific errors: (1) 400 validation error: the exact error message from the server is shown in both toast and the dialog, e.g., "Response text cannot be empty", (2) 404 "not found": "This draft was already sent or no longer exists. Refresh the ticket to see its current state.", (3) 502 SMTP error: "The email server rejected the message. Check the mailbox settings (SMTP) and try again.", (4) 0 (network offline): "You're offline. Your reply is kept here — try again when you're back online.", (5) 500 or unknown: "Sending failed. Your reply is kept here — try again." All error messages keep the draft text in the composer so the user's edits aren't lost.

What happens if the agent closes the ticket without sending?Basic

If the agent has unsaved edits (isDirty=true, meaning the text differs from the AI's original), a confirmation dialog appears: "Close this ticket? Your reply edits stay saved on this device." If the agent chooses "Close", the ticket drawer closes but the localStorage draft persists. On reopening the ticket, the locally-stored text is recovered. If there are no unsaved edits, the drawer closes immediately without prompting.

What database state changes occur after a successful send?Advanced

Three tables are updated atomically in order: (1) auto_responses: the response row is updated with sent=true, sent_at={current_timestamp}, and response_text={agent's_edited_text} (so the exact text the agent sent is preserved, not the original AI text), (2) tickets: status="Resolved" and sla_resolved_at={current_timestamp}. If sla_first_response_at is null (first response), it's also set to now, (3) audit_logs: a new entry is created with action="response_sent", ticket_id, and details including response_id, recipient email, and edited=true flag. None of these updates cascade or affect other tickets or emails.
