Decisions & Trade-offs

Every significant design decision in the project, written as an interviewer would ask it: what was chosen, what the alternatives were, and why. Each answer is tied to the file where the decision lives. Database-specific decisions (normalization, constraints, migrations) are covered in depth in Database Design & Migrations; this page summarizes them and covers everything else.

Product & scope

Why is IntelliDesk built as an internal, white-label, admin-led tool instead of a self-service helpdesk?Basic

The target is a small company that wants its own support desk: one workspace per company, an admin who connects the company mailbox and decides who works on what, and agents who only see their own tickets. That drove concrete decisions: public signup is off by default, members are added by an admin with a one-time password, only admins assign tickets, and each workspace can bring its own AI key so AI costs are billed to the company, not the platform.

src/app/api/auth/signup/route.ts; src/app/api/team/route.ts; src/server/auth/policy.ts; src/server/gemini/client.ts (getAiContext)
Why can't agents assign tickets to themselves?Intermediate

Self-assignment lets people cherry-pick easy tickets and leaves hard ones unowned. In a small team, a lead distributing work is the norm. So assignment is an admin capability enforced at three layers: the UI shows the assign menu only to admins, the API checks can.assignTickets, and the assign_ticket() database function re-checks that the actor is an active admin of the same organization. PATCH /api/tickets/[id] explicitly rejects assigned_agent, so there's no side door.

src/app/api/tickets/[id]/assign/route.ts; src/app/api/tickets/[id]/route.ts (server-owned fields rejected); supabase/migrations/013_normalize_contract.sql:30-80
How does "tickets needing human review go to an available person" work without automatic routing?Intermediate

Flagged, unassigned, open tickets collect in a Needs Review queue (?view=review). When the admin opens the assign menu, candidates come from /api/team/workload, ranked available-first, then by fewest open tickets. The admin makes the final call. Automatic round-robin was considered and rejected for the MVP: a wrong automatic assignment in a 3-person team costs more than one click, and it keeps the "only admins assign" rule absolute.

src/app/api/tickets/route.ts (view=review); src/app/api/team/workload/route.ts
Why must the whole thing run on free tiers, and what did that constrain?Intermediate

It's a college project with no budget. Consequences: Vercel Hobby only allows a daily cron, so mailbox polling every 10 minutes runs from GitHub Actions (free for public repos); no paid queue service, so the intake queue is rows in the emails table drained by HTTP-triggered runs; Gmail is connected with an app password over IMAP/SMTP instead of the Gmail API (OAuth verification for a public app is a long process); Gemini Flash and Pinecone's free tier for AI and vectors.

.github/workflows/poll-mailboxes.yml; vercel.json; src/server/email/intake.ts
Vendor facts, not code facts Vercel Hobby prohibits commercial use and Supabase free projects pause after a week of inactivity; a paying customer would need Vercel Pro and Supabase Pro (backups).

Architecture & code organization

Why is server-only code in src/server/ instead of src/lib/?Intermediate

Anything that touches secrets (the Supabase service-role key, mailbox passwords, AI keys) must never be bundled into the browser. Server modules start with import "server-only" (the build fails if a client component imports them) and ESLint's no-restricted-imports forbids importing @/server/* from client code. src/lib/ holds only code that is safe on both sides (formatting, the API client, the timezone helper). Pure modules that have no secrets and are unit-tested, like the automated-mail detector, deliberately don't import server-only so Node's test runner can load them.

eslint.config.mjs (no-restricted-imports); src/server/email/automated.ts:1
Why feature folders (src/features/<domain>) and no barrel index.ts files?Basic

Code that changes together lives together: the ticket workspace's components, hooks and helpers are all under src/features/ticket-workspace/, while src/components/ui holds only generic primitives. There are no barrel re-export files because they hide real import paths, create circular-import traps, and defeat tree-shaking; every import names the actual file.

src/features/* (8 domains, 37 files); README.md (Conventions)
Why SWR polling every 30 seconds instead of realtime (websockets / Supabase Realtime)?Intermediate

Supabase Realtime authorizes through Postgres RLS with Supabase Auth JWTs. This app uses NextAuth and keeps the Data API closed to browser roles entirely, so realtime would require a second auth system just for subscriptions and re-opening the database to the browser. For a support queue, 30-second freshness plus revalidation after every mutation is enough. The top bar shows whether the last refresh succeeded.

src/lib/sync-status.ts:6 (REFRESH_INTERVAL_MS = 30_000); src/hooks/use-api.ts
Why a central authorization policy module instead of role checks inside each route?Intermediate

With checks scattered across 24 routes, one forgotten if becomes a hole, and "what can a viewer do?" can't be answered by reading one file. can.* in policy.ts is the single source of truth (viewTicket, workTicket, assignTickets, manageSettings…), routes call it, and pages use requirePageRole. The database repeats the critical rules (assignment, tenant keys) as a last line of defense.

src/server/auth/policy.ts; src/server/auth/page-guard.ts
Why does an agent get 404, not 403, for a ticket that isn't theirs?Intermediate

A 403 confirms the ticket exists, which lets someone probe ids. Returning the same 404 for "doesn't exist" and "not yours" leaks nothing. 403 is reserved for the case where the caller may see the ticket but not act on it (a viewer trying to reply).

src/app/api/tickets/[id]/route.ts:60
Why do cron/webhook routes use a bearer secret and fail with 503 when it's unset?Intermediate

Cron callers (GitHub Actions, Vercel Cron) have no user session, so they authenticate with a shared secret compared in constant time. If the environment variable is missing, the route returns 503 instead of running unprotected: a misconfiguration fails closed rather than exposing an endpoint anyone could call.

src/server/auth/cron.ts (verifyCronRequest, timingSafeEqual)

Email handling

Why store an email before marking it read, and why a queue in the database?Advanced

Serverless functions get killed at their time limit. The original code marked mail read when it fetched it, so a timeout mid-run lost that mail forever. Now each message is durably stored (processed = false) before \Seen is set: a crash leaves it unread and it is fetched again (at-least-once delivery; storage is idempotent on Message-ID). Processing then drains the stored queue within a 50-second budget; whatever doesn't fit waits for the next run.

src/server/email/imap.ts:48, 96-101; src/app/api/emails/poll/route.ts:13; src/server/email/intake.ts

A database table is the queue because it's free, transactional, and the rows are the data anyway. Rows are claimed with a compare-and-set on processing_attempts so overlapping runs never process the same email, and after 5 failed attempts a message is parked with its error (a poison-message limit) instead of retried forever.

src/server/email/intake.ts:16, 127-136
Why is an email marked processed only at the very end of the pipeline?Advanced

If it were marked processed earlier (as it originally was), a failure afterwards left an email that was "done" but on no ticket. Now the commit point is record_inbound_message(), which is idempotent per email, and processed = true is the last write. Any failure leaves the email queued, and a retry safely lands on the same ticket.

src/server/pipeline/processor.ts:236, 313
Why "record intent, then send, then complete" for outgoing replies?Advanced

SMTP can't be part of a database transaction. So a reply is first inserted as a message with delivery_status = 'sending', then handed to SMTP with our own Message-ID, then recorded atomically by complete_ticket_reply(). A failed send becomes a visible "Not delivered" message, and a crash between send and record leaves a visible "sending" row instead of silently losing the fact that the customer got an email. It is the same idea as the transactional outbox pattern, applied without a separate worker.

src/server/tickets/replies.ts:12, 158, 169, 193
Why set our own Message-ID on outgoing mail?Intermediate

Email threading works through In-Reply-To/References headers. If we know the Message-ID of every reply we send (stored in emails as an outbound row), a customer's answer carries it in In-Reply-To and matches the right ticket exactly, which is more reliable than subject matching. All threading lookups are scoped to the organization, so an id that happens to exist in another workspace can never attach mail there.

src/server/email/smtp.ts (newMessageId); src/server/email/thread-detector.ts
Why Gmail app passwords over IMAP instead of "Sign in with Google"?Intermediate

Reading Gmail through OAuth uses restricted scopes that require Google's app verification and a security assessment before real users can connect, which isn't feasible for this project. An app password over IMAP/SMTP works with any Google account that has 2-Step Verification, and the same code supports any provider (Outlook, Zoho) through the "Other provider" option. The connect form walks the admin through creating the app password; credentials are verified with a real login before anything is saved, then encrypted.

src/features/settings/components/mailbox-form.tsx; src/app/api/settings/email-config/route.ts

AI

Why is automatic sending off by default, and why a separate policy module?Advanced

An AI email that promises a refund or quotes a wrong price can't be taken back. Production AI agents (Intercom Fin, Zendesk AI) roll out as drafts first and expand automatic answers per topic. Here, a strong knowledge-base match only makes a reply eligible; decideAutoSend can only say no, and says no unless every rule passes: the workspace opted in, low-risk category, calm sentiment, not flagged, human sender, and at most 2 automatic replies per address per day. Keeping the rules in one module makes them auditable and easy to explain.

src/server/pipeline/auto-reply-policy.ts:11-19, 41-61; supabase/migrations/011_ai_settings_and_spam_review.sql:15-16
Why does an AI outage leave emails in the queue instead of creating tickets with default labels?Advanced

The original classifier caught every error and returned made-up defaults, so a Gemini outage produced tickets labelled "General Inquiry, P3". Now Gemini calls retry transient failures with exponential backoff and jitter; if they still fail, the error propagates and the email stays queued for the next run. Only when the model answers but unusably does the pipeline fall back to "needs human review" defaults. A permanently failing workspace key is flagged in Settings.

src/server/gemini/client.ts:24-31, 56, 71-80; src/server/gemini/classify.ts
Why let each workspace bring its own Gemini key?Intermediate

For a white-label product the customer should pay their own (tiny) AI bill directly to Google, while the platform charges a flat fee; a shared key would make the platform pay for everyone's usage and hit one rate limit for all tenants. The key is verified with a free countTokens call, encrypted like the mailbox password, and the platform key is only a fallback.

src/server/gemini/client.ts (getAiContext); src/app/api/settings/ai/route.ts
Why keep Gemini instead of switching AI providers?Basic

Gemini Flash has a free tier and very low paid prices, supports JSON-schema output and system instructions (both used for safety), and provides the embedding model used for Pinecone. All model access is isolated in src/server/gemini/, so a provider change would touch one folder.

src/server/gemini/generate.ts; src/server/gemini/embeddings.ts

Security

Why AES-256-GCM with the organization id as associated data for stored secrets?Advanced

Mailbox passwords and AI keys must be recoverable (we log in with them), so they're encrypted, not hashed. GCM is authenticated encryption: tampering is detected. Binding the organization id as additional authenticated data means a ciphertext copied into another organization's row fails to decrypt, so even a database-level mix-up can't hand one tenant another's credentials. The v1: prefix leaves room for key rotation.

src/server/crypto/secrets.ts:12-13, 38-39, 50-51
Why re-check the user every 5 minutes when the JWT is valid for 30 days?Intermediate

Stateless JWTs can't be revoked. Without re-checking, a deactivated or demoted member keeps access until the token expires. The JWT callback re-reads role, active flag and organization every 5 minutes and ends the session if the account is inactive: near-immediate revocation for one small query per user every few minutes.

src/server/auth/config.ts:104-105, 130
Why always run bcrypt at login, even for unknown emails?Intermediate

If unknown emails returned immediately while known ones spent ~200 ms in bcrypt, response time would reveal which emails have accounts. Comparing against a real dummy hash makes both paths take the same time. Combined with throttling (5 failures per email and 20 per IP in 15 minutes), this blocks both account enumeration and brute force.

src/server/auth/config.ts:68, 132-137

UI & design

Why does the ticket queue use CSS container queries instead of viewport breakpoints?Intermediate

The same queue renders full-width on its own page and inside the narrower Command Center next to other panels. Viewport breakpoints would hide columns based on the window, not the space the list actually has. Container queries let the list drop columns based on its own width, with the breakpoints shared between header and rows so they never misalign.

src/features/queue/lib/grid.ts; src/features/queue/components/queue-list.tsx
Why is AI output always visibly labelled?Basic

Agents must know what a human verified versus what a model suggested. AI summaries, drafts and automatically-sent replies all carry the IntelliDesk AI mark ("AI suggestion", "AI draft", "Sent automatically"), and the confidence is shown as a 5-segment meter with a text band rather than a false-precision percentage.

src/components/ui/ai-mark.tsx; src/components/ui/confidence-meter.tsx; src/features/ticket-workspace/components/conversation-column.tsx
Why does the app live at the repository root?Basic

It was reorganized from a nested frontend folder into a single Next.js app at the root, so Vercel builds it with default settings (empty Root Directory) and tooling (ESLint, TypeScript, the Supabase CLI, npm test) runs from one place.
