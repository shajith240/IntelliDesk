AI Design & Safety

The AI never takes actions: it has no tools, can't change a ticket's status, assign, refund or delete. It produces text and labels that code and people decide what to do with.

Whose API key does a call use?Intermediate

Each workspace can save its own Gemini key in Settings → AI (the customer pays Google directly). The key is format-checked, verified with a free countTokens call, encrypted with AES-256-GCM (organization id as associated data) and stored in ai_credentials; only the last four characters are ever shown. getAiContext uses that key, falls back to the platform GEMINI_API_KEY, and otherwise throws AiNotConfiguredError so email waits in the queue. Saving a working key requeues emails that gave up while AI was unavailable.

Prompt design & prompt injection

How do you stop a customer's email from giving the model instructions?Advanced

Four layers, following OWASP's LLM guidance:

  1. Separation: instructions go in the model's system instruction; the customer's text only ever appears in the user content.
  2. Delimiting: untrusted text is wrapped in tags such as <customer_email>, and any matching tag inside the text is stripped first, so an email can't "close" the block and continue as instructions.
  3. Explicit rule: the prompts say the tagged content is data, list typical injection phrasing, and tell the classifier to flag such attempts for human review.
  4. Constrained output: responses must match a JSON schema, and the model has no tools — the worst a successful injection can do is produce text, which then has to pass the grounding check and the auto-send policy.
export function untrusted(tag: string, text: string): string {
	const safe = text.replace(new RegExp(`</?${tag}\\b[^>]*>`, "gi"), "");
	return `<${tag}>\n${safe}\n</${tag}>`;
}

Why structured (JSON-schema) output?Intermediate

The old code asked for JSON in prose and stripped markdown fences with regexes, which broke whenever the model added commentary. Gemini's responseSchema constrains output to an object with enum-restricted fields (category, severity, language, sentiment). Values are still validated in code, because a schema is a constraint on the model, not a guarantee to rely on blindly.

Grounded replies

How is a reply draft produced?Advanced
  1. P1/P2 tickets get no draft — urgent issues always need a person.
  2. The email is embedded and the top 5 articles in the workspace's faqs namespace (same category) are retrieved; articles are re-read from Postgres with the organization filter.
  3. Below 0.7 similarity: no draft.
  4. The model writes a reply using only the top 3 articles and returns { answerable, reply, reason }. If it says the articles don't answer the question, there is no draft.
  5. The grounding check runs on the reply.
  6. A draft is eligible for automatic sending only with similarity ≥ 0.9 and no ungrounded facts; otherwise it's a suggestion for an agent.
  7. The draft is stored with its citations (auto_response_citations: which articles, rank, score).
src/server/gemini/respond.ts:12-13, 36, 69-90; src/server/pipeline/processor.ts (draftOrSendAutoResponse)
What is the grounding check?Advanced

A deterministic check that every link, email address, phone number and money amount in the reply appears in the cited articles. These are the facts that do real damage when invented ("we'll refund $500", a phishing link planted by the customer's email). If anything is found, the reply can still be a draft, but it is never sent automatically, and the draft's reasoning lists what was found.

const patterns = [
	/\bhttps?:\/\/[^\s)>\]]+/gi,
	/\bwww\.[^\s)>\]]+/gi,

The previous code had a fallback that, when generation failed, emailed the raw FAQ answer signed as the support team. It was removed: unusable model output now means no draft.

Automatic sending policy

When may an AI reply be emailed without a person approving it?Advanced

Only when every one of these holds — decideAutoSend can only say no:

#RuleWhy
1The workspace turned on "Send confident answers automatically" (off by default)Explicit opt-in; drafts-only is the safe default
2It's a new ticket (never a follow-up in an existing conversation)Customers writing back want a person, and it prevents reply ping-pong
3Strong match (≥ 0.9) and grounded (see above)No invented facts
4Priority P3/P4Urgent issues need a person
5Category is How-To, General Inquiry, Feature Request or Technical SupportBilling, access, data requests and complaints always go to a person
6Not flagged for human review; sentiment isn't negative or angryUpset customers get a human
7Sender isn't automated (lists, bulk, no-reply)Never answer robots
8Fewer than 2 automatic replies to that address in the last 24 hHard rate limit, whatever else happens

What happens when an automatic reply is sent?Intermediate

It goes through the same sendTicketReply path agents use, as an AI-authored message: our own Message-ID, threading headers, Auto-Submitted: auto-replied, and the ticket moves to Pending (waiting on the customer). If the customer writes back, the ticket reopens and a person answers. In the conversation the message shows as "IntelliDesk AI — Sent automatically". A failed send leaves the draft unsent for an agent.

Mail loops

How does the system avoid answering robots and starting mail loops?Advanced

Every inbound email is classified before any AI call:

KindDetected byHandling
ownFrom address = the workspace's own mailboxStored, never ticketed

bulkPrecedence: bulk/junk/list, List-* headers (RFC 2369/2919), no-reply sendersTicketed, never auto-answered

In the other direction, our automatic replies carry Auto-Submitted: auto-replied and X-Auto-Response-Suppress: All, so well-behaved autoresponders don't answer them. Together with the 2-per-day cap, two auto-responders can't bounce off each other.

Reliability & human oversight

What happens when Gemini fails?Advanced
  • Transient errors (429, 5xx, network) are retried after about 1 s and 4 s with jitter.
  • If it still fails, AiCallError propagates and the email stays in the intake queue for the next run (up to 5 attempts, then parked with its error).
  • A permanent failure of a workspace key (invalid, forbidden) marks the key error with a message shown in Settings.
  • Only when the model responds but the output is unusable does classification fall back to safe defaults with requires_human_review = true.

The earlier behaviour — catching every error and creating a ticket labelled "General Inquiry, P3" — was a bug: an outage silently produced wrong data.

src/server/gemini/client.ts (withRetry, AiCallError, recordAiKeyFailure); src/server/gemini/classify.ts:135-150
When does the classifier send a ticket to human review?Basic

When the model's confidence is below 0.8, or it sets requires_human_review itself — the prompt tells it to for refunds, cancellations, legal or security matters, angry customers, suspected injection attempts, or uncertainty. Flagged, unassigned tickets appear in Needs Review for an admin to assign.

src/server/gemini/classify.ts:62-63, 129
How is AI output presented to people?Basic

Always labelled: the AI summary card ("AI suggestion", with a confidence meter), the reply composer ("AI draft" with the match strength), and automatically sent messages ("Sent automatically"). An agent can edit the draft or write from scratch, and every reply needs an explicit confirmation that shows the recipient and the status the ticket will be left in. The draft's original text is kept when an edited version is sent, so the AI's suggestion and what was actually sent can be compared.

What are the AI system's known limitations?Intermediate
Not implemented
  • No measurement of AI answer quality (agent thumbs up/down, edit distance between draft and sent text is stored but not reported).
  • Replying in the customer's language relies on a prompt instruction only.
  • Attachments are ignored, so screenshots and invoices aren't seen by the AI.
  • No per-topic auto-send configuration; the allowlist is fixed in code.
