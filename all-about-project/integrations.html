Supabase & Pinecone

How does the app connect to Supabase, and why only with the service role?Intermediate

A single lazily created client with the service-role key, exposed through a proxy so importing the module has no side effects. The service role bypasses RLS, which is fine because it exists only on the server and every query filters by organization. Browser roles (anon, authenticated) have no privileges at all since migration 006, so the public anon key can't read anything.

src/server/db/supabase.ts:1-20; supabase/migrations/006_lockdown_public_api.sql:55-63
How is Pinecone organized?Intermediate

One index, with a namespace per organization and purpose: {orgId}_emails (duplicate detection), {orgId}_tickets (similar tickets, search), {orgId}_faqs (knowledge-base retrieval). Vector ids are the Postgres row ids, which is why no embedding_id column is needed. Every upsert and query checks the vector dimension against PINECONE_EMBEDDING_DIMENSIONS (default 768), and deleteVectors removes an article's vector when the article is deleted.

src/server/auth/org-context.ts:20-22; src/server/db/pinecone.ts:11-12, 28-30
Why truncate Gemini embeddings to 768 dimensions?Advanced

gemini-embedding-001 returns 3072 dimensions, and the installed SDK doesn't expose the output-dimensionality option. The model is trained with Matryoshka representation learning, so the leading dimensions carry most of the meaning: the code takes the first N values and re-normalizes to unit length so cosine similarity stays valid, matching whatever dimension the Pinecone index was created with.

src/server/gemini/embeddings.ts:1-20

Gemini

Which key does an AI call use?Intermediate

getAiContext(orgId) decrypts the workspace's own key from ai_credentials if one is saved; otherwise it uses the platform GEMINI_API_KEY; with neither it throws AiNotConfiguredError and the email waits in the queue. The context carries its source so a failing workspace key can be flagged in Settings.

src/server/gemini/client.ts (getAiContext, recordAiKeyFailure)
How are Gemini failures handled?Advanced

Every call goes through withRetry: transient errors (429, 5xx, network) retry after ~1 s and ~4 s with ±25% jitter; permanent ones (bad key, forbidden model) fail immediately. Failures surface as AiCallError with a transient flag. User-facing routes translate them with aiErrorResponse (503 "AI isn't set up" / "busy", 502 for a bad key); the pipeline lets them propagate so the email is retried later.

src/server/gemini/client.ts:24-31, 56, 71-80 (RETRY_DELAYS_MS, toAiCallError, aiErrorResponse)

Email (IMAP / SMTP)

How is a mailbox connected?Intermediate

Gmail uses fixed settings (IMAP imap.gmail.com:993, SMTP smtp.gmail.com:587) and a 16-letter app password; any other provider supplies hosts with IMAP on 993 and SMTP on 465 or 587. Before saving, custom hosts must resolve to public IP addresses (SSRF guard), and the server performs a real IMAP login and SMTP handshake. Only then is the password encrypted and stored in mailbox_connections (one per workspace). The secret is never returned by the API.

src/server/email/mailbox.ts (GMAIL_SETTINGS, assertPublicMailHost, verifyMailboxCredentials); src/app/api/settings/email-config/route.ts
What transport security is enforced?Intermediate

IMAP always uses implicit TLS on 993 with certificate verification. SMTP uses implicit TLS on 465 and requires STARTTLS on any other port (requireTLS), with certificate verification and TLS 1.2 minimum, so credentials are never sent in clear text. Connection, greeting and socket timeouts keep a dead server from hanging a serverless function.

src/server/email/smtp.ts:13-26; src/server/email/mailbox.ts:185-190
What does fetching and sending look like?Advanced

Fetching: unseen INBOX messages from the last two days are collected first, then each is parsed with mailparser, handed to the store callback, and only then flagged \Seen (unparseable messages are marked seen so they don't block the queue).

Sending: every outgoing email gets our own Message-ID on the mailbox's domain plus In-Reply-To/References of the conversation, a header-safe subject (no CR/LF), and a From display name set to the organization name. Automatic AI replies also carry Auto-Submitted: auto-replied and X-Auto-Response-Suppress: All so other systems don't answer them.

src/server/email/imap.ts:47-101; src/server/email/smtp.ts (sendEmail, newMessageId, headerSafe)
How are mailbox problems surfaced?Basic

Each poll or send records its outcome with recordMailboxSync: success sets status = active and last_synced_at; failure sets status = error and a human-readable last_error from describeMailboxError (e.g. "use a 16-character app password"). The Settings card shows "Needs attention" with that message and a Reconnect button.

src/server/email/mailbox.ts (recordMailboxSync, describeMailboxError); src/features/settings/components/mailbox-form.tsx

Scheduling & hosting

How does the GitHub Actions schedule work?Basic
on:
  schedule:
    - cron: "*/10 * * * *"
  workflow_dispatch: {}

permissions: {}

concurrency:
  group: poll-mailboxes
  cancel-in-progress: false
.github/workflows/poll-mailboxes.yml:9-19

The job has no repository permissions, never runs twice at once, and skips with a warning if APP_URL or CRON_SECRET isn't configured. It fails the workflow run if the endpoint doesn't return 200, which makes intake problems visible in GitHub.

What vendor limits matter for this project?Basic
Vendor facts (not verified in code)
  • Vercel Hobby: cron at most daily (hence GitHub Actions); commercial use not permitted — a paid customer needs Vercel Pro.
  • Supabase free: 500 MB database; projects pause after about a week without activity (the 10-minute poll keeps it active); no automatic backups.
  • Pinecone Starter: a limited number of vectors on the free plan; enough for a small team.
  • Gemini free tier: rate-limited, and Google may use free-tier data to improve its models — the Settings page tells admins to use a paid key for customer data.
  • GitHub Actions schedules can run a few minutes late under load.
