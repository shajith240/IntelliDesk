External Services & Integrations

The four external services that power this application: Supabase for data persistence, Pinecone for semantic search, Google Gemini for AI classification and embeddings, and IMAP/SMTP for email ingestion and sending. Each is accessed via a server-only client initialized as a singleton.

Supabase (PostgreSQL database)

How is Supabase used in this application?Basic

Supabase provides the PostgreSQL database and storage for all persistent data: organizations, users, tickets, emails, SLA policies, knowledge-base articles, and audit logs. The app uses the Supabase service-role client (not the anon key) from all route handlers, which bypasses row-level security policies and requires explicit organization filtering in every query.

Row-level security (RLS) policies in the database prevent unauthorized access at the SQL layer as a defense-in-depth measure. Mailbox credentials (IMAP/SMTP) are also stored in Supabase under email_config, encrypted at rest and fetched per-organization when the cron job runs.

How is the Supabase service-role client initialized?Intermediate

The Supabase client is initialized as a lazy singleton using a Proxy pattern in src/server/db/supabase.ts:

import "server-only";
import { createClient, type SupabaseClient } from "@supabase/supabase-js";

let _supabaseAdmin: SupabaseClient | null = null;

function getSupabaseAdmin(): SupabaseClient {
  if (!_supabaseAdmin) {
    const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL!;
    const serviceRoleKey = process.env.SUPABASE_SERVICE_ROLE_KEY!;
    _supabaseAdmin = createClient(supabaseUrl, serviceRoleKey);
  }
  return _supabaseAdmin;
}

export const supabaseAdmin = new Proxy({} as SupabaseClient, {
  get(_target, prop) {
    const client = getSupabaseAdmin();
    const value = (client as unknown as Record)[prop];
    if (typeof value === "function") {
      return value.bind(client);
    }
    return value;
  },
});

The Proxy intercepts property access and returns the singleton client. This pattern ensures the client is initialized on first use and reused thereafter, reducing connection overhead in serverless functions. Every function call is bound to the client instance.

Pinecone (vector search)

What is Pinecone used for, and how is it configured?Basic

Pinecone stores vector embeddings of every ticket and knowledge-base article, indexed by organization namespace. During the email pipeline, each new ticket's embedding (generated by Gemini) is upserted to Pinecone. When drafting a reply, the pipeline queries Pinecone for the top 5 most similar knowledge-base articles and uses them to prompt Gemini for a reply draft.

Configuration is split between environment variables:

  • PINECONE_API_KEY — API authentication
  • PINECONE_INDEX — Index name (default "intellidesk")
  • PINECONE_HOST — Optional direct index host for performance (Pinecone provides this in the console)
  • PINECONE_EMBEDDING_DIMENSIONS — Must match both the index creation dimension and Gemini's embedding model output (currently 3072 for gemini-embedding-001)

How does Pinecone enforce embedding dimension correctness?Intermediate

Before upserting or querying, the Pinecone client validates vector dimensions against EMBEDDING_DIMENSIONS. This prevents silent mismatches between the index and incoming vectors:

export const EMBEDDING_DIMENSIONS = Number(
  process.env.PINECONE_EMBEDDING_DIMENSIONS || 768,
);

export async function upsertVectors(
  namespace: string,
  vectors: {
    id: string;
    values: number[];
    metadata: RecordMetadata;
  }[],
) {
  // Validate vector dimensions before upserting
  for (const v of vectors) {
    if (v.values.length !== EMBEDDING_DIMENSIONS) {
      throw new Error(
        `Vector dimension mismatch: expected ${EMBEDDING_DIMENSIONS}, got ${v.values.length}. ` +
        `Ensure you are using gemini-embedding-001 which produces ${EMBEDDING_DIMENSIONS}-dimensional vectors.`
      );
    }
  }
  // ... upsert proceeds
}

If a vector dimension is incorrect (e.g., a different embedding model produces 1024 dimensions instead of 3072), the error is thrown immediately with a helpful message before any data is written. Query vectors are similarly validated.

Google Gemini (AI classification and embeddings)

What does Gemini do in this application, and how is it used?Basic

Gemini is used for three tasks:

  • Message classification — Every incoming email is sent to Gemini with a structured prompt to classify its category (Technical Support, Billing/Invoice, etc.), priority (P1-P4), sentiment, and confidence score. The response is stored on the ticket.
  • Embeddings — Each ticket and FAQ article is embedded via Gemini's embedding model (gemini-embedding-001) to produce a 3072-dimensional vector, which is stored in Pinecone for semantic search.
  • Reply drafting — When an agent opens a ticket, the pipeline queries Pinecone for the top knowledge-base articles, sends them to Gemini with the ticket context, and generates a draft response. The agent reviews and confirms before sending.

How is the Gemini client initialized?Basic

The Gemini client uses a similar lazy-singleton pattern to Supabase:

import "server-only";
import { GoogleGenerativeAI } from "@google/generative-ai";

let genAI: GoogleGenerativeAI | null = null;

export function getGenAI(): GoogleGenerativeAI {
  if (!genAI) {
    genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY!);
  }
  return genAI;
}

export function getModel(modelName: string = "gemini-2.5-flash") {
  return getGenAI().getGenerativeModel({ model: modelName });
}

The getModel() helper abstracts model selection, defaulting to gemini-2.5-flash but allowing override. This avoids instantiating the client multiple times across different route handlers.

Email (IMAP and SMTP)

How does the application ingest emails via IMAP?Intermediate

The pollNewEmails() function in src/server/email/imap.ts runs on every cron job invocation:

  • Fetches the organization's IMAP configuration from Supabase (email_config table).
  • Connects to the mailbox via the imapflow library (pure IMAP, no OAuth relay).
  • Queries unseen emails from the last 2 days (to avoid bulk-importing old inbox history on first run).
  • For each message, uses mailparser's simpleParser() to extract headers, body (text + HTML), from/to/subject, references, and message ID.
  • Marks the email as seen in the mailbox (best-effort; failures are logged and don't block).
  • Returns a RawEmail object for pipeline processing.

The processedUIDs in-memory set tracks emails that were parsed successfully to avoid re-processing if the mailbox's seen flag doesn't persist (edge case on slow connections).

How does the application send replies via SMTP?Intermediate

The sendEmail() function in src/server/email/smtp.ts uses nodemailer to send email replies:

export async function sendEmail(options: SendEmailOptions): Promise {
  const transporter = getTransporter(options.smtpConfig);
  if (!transporter) {
    console.warn("SMTP credentials not configured, skipping send");
    return false;
  }

  const user = options.smtpConfig!.user;

  try {
    await transporter.sendMail({
      from: `"IntelliDesk AI Support" <${user}>`,
      to: options.to,
      subject: options.subject,
      text: options.text,
      html: options.html,
      inReplyTo: options.inReplyTo,
      references: options.references?.join(" "),
    });
    return true;
  } catch (err) {
    console.error("SMTP send error:", err);
    return false;
  }
}

The function returns true on success or false if credentials are missing. SMTP configuration (host, port, username, password) comes from the organization's email_config row in Supabase, not from environment variables. The inReplyTo and references headers preserve the email thread.

What email parsing utilities exist for cleaning and extracting data?Basic

The src/server/email/parser.ts module provides several utilities for processing email content:

  • stripHtml() — Removes HTML tags and entities, leaving plain text for embedding and classification.
  • cleanEmailBody() — Removes quoted replies and forward markers (lines starting with ">" or "On ... wrote:") to isolate the new message content.
  • extractSignature() — Extracts the sender's name, role, company, email, and phone from the signature block using regex patterns.
  • isLikelySpam() — Scores the email against keywords and sender patterns (marketing, automated, newsletters) and returns true if spam confidence is high. This avoids creating tickets for unwanted emails.
  • normalizeSubject() — Removes "Re:", "Fwd:", and bracketed tags from the subject to identify threads correctly.
  • detectLanguage() — Detects if the email body contains Hindi (Devanagari) characters, returning "hindi", "mixed", or "english".
  • extractTicketReferences() — Finds ticket numbers in the email body using patterns like "#12345", "Ticket-123", or "TKT-00001".
